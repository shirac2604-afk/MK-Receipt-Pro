# Sprint 2 — שלב ב׳: Stress Tests

**מוצר:** מפתחות להצלחה  
**גרסה שנבדקה:** 1.0.0-rc.1  
**מועד:** 30/07/2026  
**סטטוס:** עבר ברמת מסד הנתונים והשאילתות; נדרשות בדיקות Windows ו-PDF מלאות.

## מטרת הבדיקה

לבדוק את יציבות רצף הקבלות, מהירות החיפוש, חישובי הדוחות, תקינות SQLite וגיבוי מסד הנתונים בנפחים של 1,000 עד 100,000 קבלות.

## מספור ושלמות

בכל ארבעת הנפחים:

- לא נמצא אף מספר קבלה כפול.
- `next_number` ו-`last_issued_number` תאמו למספר הקבלות שנוצרו.
- `PRAGMA integrity_check` הסתיים בהצלחה.
- גיבוי המסד עבר דחיסה, פתיחה מחדש והשוואת SHA-256.

בבדיקת 100,000 קבלות:

```text
מספר אחרון: 101000
מספר הבא:   101001
כפילויות:   0
```

## ביצועי חיפוש

ב-100,000 קבלות:

- איתור מספר קבלה מדויק: 0.06 ms.
- חיפוש לפי לקוח: 6.78 ms.
- חיפוש משולב: 10.70 ms.
- טעינת עמוד עמוק של 50 רשומות: 2.28 ms.

היעד שהוגדר לחיפוש ב-100,000 קבלות היה עד שנייה אחת. התוצאה בבדיקת הליבה נמוכה משמעותית מהיעד.

## ביצועי דוחות

ב-100,000 קבלות:

- סיכום טווח שנתי: 96.96 ms.
- פירוט חודשי: 41.57 ms.

היעד שהוגדר לדוח שנתי היה עד שנייה אחת. בדיקת הליבה עברה את היעד.

## ביצועי גיבוי מסד

ב-100,000 קבלות:

- דחיסת מסד: 717.54 ms.
- אימות ופתיחה מחדש: 240.86 ms.
- גודל מסד: 34.05 MB.
- גודל דחוס: 11.11 MB.

בדיקה זו כוללת את מסד הנתונים בלבד. חבילת הגיבוי המלאה של המוצר כוללת גם קובצי PDF, לוגו וחתימה; משך גיבוי כזה תלוי בכמות ובגודל הקבצים.

## מגבלות הבדיקה

הבדיקה הנוכחית אינה מוכיחה עדיין:

- זמן יצירת 2,000 או יותר קובצי PDF אמיתיים דרך Chromium/Electron.
- גיבוי מלא עם אלפי קובצי PDF.
- צריכת זיכרון של ממשק React במשך יום עבודה.
- ביצועי המתקין, Windows Defender או כונן איטי.
- מהירות במחשב העבודה בפועל.
- התנהגות במסך תחת DPI של 125%–150%.

אלה ייבדקו ידנית על Windows במהלך Release Candidate.

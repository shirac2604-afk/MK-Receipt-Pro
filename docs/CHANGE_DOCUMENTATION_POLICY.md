# כלל מחייב: תיעוד שינויים ב-GitHub

## הכלל

כל שינוי בפרויקט מתועד ב-GitHub **באותו ענף עבודה ולפני שהוא נחשב הושלם**. הכלל חל על קוד, הגדרות, אבטחה, תלויות, CI, מסמכים, build והוראות הפעלה.

## מה חייב להיכלל

1. Commit ברור המתאר מה השתנה ולמה.
2. Pull Request הכולל את ההשפעה, הסיכון, תוצאות הבדיקות ומה עדיין דורש בדיקה ידנית.
3. עדכון `CHANGELOG.md` לכל שינוי מהותי או שינוי שמשפיע על אבטחה, שדרוג, build או משתמש.
4. עדכון מסמך ההפעלה או האבטחה המתאים כאשר משתנים צעדי התקנה, הרשאות, הגדרות Supabase או התנהגות אבטחה.
5. ציון אם זהו שינוי מקור בלבד, אם נדרשת בנייה חדשה, ואם השדרוג נשאר in-place עם מזהי האפליקציות הקיימים.

## גבולות שחרור

- תיעוד ב-GitHub אינו מחליף בדיקות CI ובדיקה ידנית של Android ו-Windows.
- אין למזג ל-`main`, לשנות Production או להפיץ build רק משום שהתיעוד נכתב. נדרש אישור מפורש ועדכני לאחר שכל השערים עברו.
- תקלת CI, פער אימות או rollback חייבים גם הם להירשם ב-PR וב-`CHANGELOG.md` כאשר הם מהותיים.
